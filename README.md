# AI Log Analyzer

A production-ready web application that ingests server/application logs, automatically redacts PII and secrets, analyzes patterns and anomalies with an LLM, and presents interactive findings on a dashboard.

---

## Features

| Category | Details |
|---|---|
| **Log Ingestion** | File upload (`.log` `.txt` `.json` `.csv`) or paste raw text |
| **Formats** | Nginx, Apache, Syslog, Python logging, Spring Boot, Node.js/Winston, JSON, CSV, generic timestamped |
| **PII Redaction** | Emails, IPv4/IPv6, Bearer tokens, API keys, passwords, credit cards, SSNs, JWTs — all redacted *before* being sent to the LLM |
| **AI Analysis** | Executive summary, error grouping, Root Cause Analysis with confidence score, remediation steps, security threat detection, anomaly detection |
| **Dashboard** | Health score gauge, log-level pie chart, error timeline, top errors bar chart, log volume chart |
| **Log Explorer** | Filter by level / source / keyword, sanitized/raw toggle, searchable table |
| **Export** | Download report as Markdown or JSON; export parsed logs as CSV |
| **LLM Providers** | OpenAI, Anthropic, or local Ollama — swappable via sidebar or `.env` |

## Quick Start

### 1. Clone / navigate to the project

```bash
cd ai-log-analyzer
```

### 2. Create and activate a virtual environment

```bash
# Python 3.11+ required
python -m venv .venv

# Windows
.venv\Scripts\activate
# macOS / Linux
source .venv/bin/activate
```

### 3. Install dependencies

```bash
pip install -r requirements.txt
```

### 4. Configure environment

```bash
cp .env.example .env
# Edit .env and add your API key:
# OPENAI_API_KEY=sk-...      (for OpenAI)
# ANTHROPIC_API_KEY=sk-ant-... (for Anthropic)
# or leave blank and use Ollama locally
```

### 5. Generate sample logs (optional but recommended)

```bash
python generate_mock_logs.py
# Writes ~1000 lines to sample_logs/mock_app.log
# Includes: DB errors, brute-force attacks, OOM, circuit breaker, PII
```

### 6. Run the application

```bash
streamlit run app.py
```

Open **http://localhost:8501** in your browser.

## Using the Dashboard

1. **Sidebar → LLM Configuration**: select provider, enter API key (or configure via `.env`).
2. **Sidebar → Log Ingestion**: upload `sample_logs/mock_app.log` or any real log file.
3. **Click "🚀 Process Logs"** — logs are parsed and PII-redacted immediately.
4. **📊 Overview tab**: review metric cards, charts, and PII redaction summary.
5. **📋 Logs tab**: explore, filter, and search log lines; toggle sanitized view.
6. **🤖 AI Insights tab**: click "▶ Run AI Analysis" to trigger LLM analysis.
7. **📥 Export tab**: download the report as Markdown or JSON.

## LLM Provider Configuration

### OpenAI
```env
DEFAULT_LLM_PROVIDER=openai
OPENAI_API_KEY=sk-...
# DEFAULT_LLM_MODEL=gpt-4o-mini  (default)
```

### Anthropic
```env
DEFAULT_LLM_PROVIDER=anthropic
ANTHROPIC_API_KEY=sk-ant-...
# DEFAULT_LLM_MODEL=claude-3-haiku-20240307  (default)
```

### Ollama (local, free)
```bash
# Install Ollama: https://ollama.ai
ollama pull llama3
ollama serve
```
```env
DEFAULT_LLM_PROVIDER=ollama
OLLAMA_BASE_URL=http://localhost:11434
# DEFAULT_LLM_MODEL=llama3  (default)
```

## Supported Log Formats

| Format | Example |
|---|---|
| **Nginx/Apache access** | `127.0.0.1 - - [15/Jun/2024:10:00:01 +0000] "GET /api HTTP/1.1" 200 512` |
| **Syslog** | `Jun 15 10:00:01 web-01 myapp[1234]: message` |
| **Python logging** | `2024-06-15 10:00:01,234 - module - ERROR - message` |
| **Spring Boot** | `2024-06-15 10:00:01.234  ERROR 12345 --- [thread] com.Class : message` |
| **Winston (text)** | `[2024-06-15T10:00:01.234Z] [INFO] message` |
| **JSON lines** | `{"time":"2024-06-15T10:00:01Z","level":"error","msg":"..."}` |
| **JSON array** | `[{"timestamp":"…","level":"…","message":"…"}, …]` |
| **CSV** | Header row with `timestamp`, `level`, `message` columns |
| **Generic** | Any line with an ISO-8601 timestamp and optional level keyword |

## PII Redaction Rules

| Category | Pattern | Replaced With |
|---|---|---|
| Email | `user@domain.com` | `[EMAIL]` |
| IPv4 | `192.168.1.1` | `[IPv4]` |
| IPv6 | `2001:db8::1` | `[IPv6]` |
| JWT | `eyJ…` | `[JWT]` |
| Bearer token | `Bearer sk-prod-…` | `[BEARER_TOKEN]` |
| API key | `api_key=ABC123` | `[API_KEY]` |
| Password | `password=secret` | `[PASSWORD]` |
| Credit card | `4532015112830366` | `[CREDIT_CARD]` |
| SSN | `123-45-6789` | `[SSN]` |

## Mock Log Generator

```bash
# Default: ~1000 lines → sample_logs/mock_app.log
python generate_mock_logs.py

# Custom line count and output path
python generate_mock_logs.py --lines 5000 --out /tmp/big_test.log

# Different seed for varied data
python generate_mock_logs.py --seed 99
```

Scenarios covered:
- ✅ Healthy baseline traffic
- 💥 Database connection pool exhaustion → cascading HTTP 500s
- 🔐 Auth brute-force attack (burst of 401s from attacker IPs)
- 🧠 JVM memory pressure + OutOfMemoryError + GC pauses
- ⚡ Downstream service timeout + Resilience4j circuit breaker
- 💾 Disk I/O error during log rotation
- 🔒 PII data (emails, credit cards, API keys, Bearer tokens, SSNs)
